# Noor — Quran Companion

An Android-first Quran study companion built with React, Vite, and Capacitor, with a responsive emerald-green and cream interface.

## Run the web development version

Install Node.js LTS, then run:

```bash
npm install
npm run dev
```

Open the localhost URL printed by Vite.

## Android app project

Install Android Studio and its Android SDK first, then run in the project folder:

```bash
npm install
npx cap add android
npm run build
npx cap sync android
npx cap open android
```

Once Android Studio opens, allow Gradle to sync. Connect an Android phone with USB debugging enabled or launch an emulator, then press **Run**. To generate a local APK use **Build → Build Bundle(s) / APK(s) → Build APK(s)**. This repository contains source code and Android packaging configuration; it does not contain a prebuilt or signed APK.

## Features in this prototype

- Searchable catalog for all 114 Surahs, with Arabic names and verse counts.
- Reading/listening progress, personal verse notes, and bookmarks.
- Per-Surah local audio uploads with seek, playback speed, and saved playback position.
- Reader controls for Arabic, Roman Urdu, Urdu script, and English translation display.
- Auto-load `public/quran-translations.json` when a verified dataset is supplied; import translations as JSON, and export/restore local user-data backups.
- Responsive mobile UI, light/dark mode, local browser storage and IndexedDB audio storage.

## Bulk audio mapping (local files)

1. Copy the 114 audio files into `public/Mairaj_Uddin_Khan/`.
2. Open PowerShell at the project root and run:

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\scripts\build-audio-manifest.ps1
   ```

3. The script creates `public/audio-manifest.json`; Vite uses it to map Surah numbers to filenames. Numeric prefixes are the most reliable, for example `001-Al-Fatihah.mp3`, `002-Al-Baqarah.mp3`, … `114-An-Nas.mp3`. The script also tries to identify Surah names in filenames and reports files it cannot match.
4. Audio files are intentionally excluded from GitHub. Keep them locally for development; the deployed app needs the audio hosted at its expected public path or a configurable audio host.

Place a verified translation dataset at `public/quran-translations.json` to load it automatically. This file is not generated by the audio script.

## Translation dataset format

For Quranic accuracy, full verse text and translations are not bundled. Import a verified dataset that you are licensed to use and ensure verse alignment, spelling, and attribution have been reviewed.

```json
{
  "verses": {
    "1": {
      "1": {
        "arabic": "verified Arabic text",
        "roman": "Roman Urdu text",
        "urdu": "اردو ترجمہ",
        "english": "English translation"
      }
    }
  }
}
```

The outer keys are Surah numbers and nested keys are verse numbers.

## Current limitations

- Audio can be mapped in bulk from `public/Mairaj_Uddin_Khan/` using `scripts/build-audio-manifest.ps1`; audio files themselves are not committed to GitHub.
- Background playback, notification controls, and Android lock-screen controls need a native audio service/plugin and real-device testing.
- Notes/progress are local to this app/browser profile. Export backups before clearing app/browser data or changing devices.
- Optional account and cloud sync require a secure backend and authentication.

## Natural Urdu and English verse voices (local development)

Urdu and English verse playback uses Microsoft Edge neural voices through the edge-tts Python package. The Arabic recitation remains a separate hosted per-ayah audio source.

Keep **two terminals** open in the project folder:

**Terminal 1 — start the speech server (Python 3.10+ recommended):**

Windows:
```powershell
py -m pip install -r requirements-tts.txt
py tts_server.py
```

macOS/Linux:
```bash
python3 -m pip install -r requirements-tts.txt
python3 tts_server.py
```

Wait until it says `Noor TTS server listening on http://127.0.0.1:8000`.

**Terminal 2 — start the React app:**
```bash
npm install
npm run dev
```

Open the localhost URL printed by Vite. Both the speech server and Vite must remain running. The speech server requires internet access because it generates neural voice audio online. It is intended for local development, not direct public deployment; production hosting needs a secured backend service.

Voice selections: English `en-US-AriaNeural`, Urdu `ur-PK-UzmaNeural`.
